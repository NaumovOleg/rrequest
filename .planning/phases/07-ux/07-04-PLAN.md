<objective>
Add a no-code "Checks" panel inside the Tests tab: rows of (target » operator »
expected) that compile into a runnable `pm.test` block. The compiled code is
written back into the request's existing testScript field, so it reuses the
whole current pipeline (sandbox + PASS/FAIL display) with zero host changes.

Purpose: cover the common 10% of assertions (status code, header, JSON field,
response time) in 30 seconds, no JavaScript required.
Output: AssertPanel (UI) + test-compile (pure serialize/parse) + integration in
the Tests sub-tab.
</objective>

<execution_context>
testScript lives on RestRequest (src/shared/types.ts) and is sent with the
request; runTestScript (src/extension/scripting/sandbox.ts) executes pm.test and
returns TestResult[] rendered as PASS/FAIL chips in ResponsePanel. The Tests
sub-tab in RequestPanel.tsx (line ~1123) is the insertion point.

Format contract (keep stable for round-trip):
- Compiled script embeds a marker comment line in exact text:
  `// rrequest:checks {"rows":[...]}`
- rows: { id, target: 'status'|'header'|'json'|'time', selector: string, op: 'eq'|'lt'|'gt', value: string }
- Compile maps each row to one pm.test with a descriptive name.
- Parse reads the marker back; absence of exact marker => null (hand-written
  script left untouched).
- Editor hand-writing: if user switches to raw Script mode and edits, the
  checks table collapses to empty (marker removed on next save only if the
  user deletes it; simplest rule: table edits always rewrite WHOLE testScript
  from current rows — mode switch is a view concern only, manual scripts when
  marker removed).
</execution_context>
