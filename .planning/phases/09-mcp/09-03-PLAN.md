<objective>
Give the agent resource-management tools that create and manage collections,
folders, and requests — all routed through the extension's existing message
router so sync, the read-only guard, trashing, and live UI updates behave exactly
as if the user did it. No request sending.

Purpose: let an AI agent populate and tidy the user's RREQUEST workspace.
Output: a gated, tested create/manage surface plus user documentation.
</objective>

<execution_context>

- **Writes reuse the router.** Each manage tool builds the same `WebviewMessage`
  the webview sends and calls `port.dispatch(msg)`. `hub.dispatch` then runs the
  read-only (viewer) guard, records sync deletions, schedules a push
  (`afterDispatch` → `schedulePush`), and broadcasts a fresh snapshot — so the
  sidebar updates live and synced workspaces push. **Do not write stores
  directly** (that path skips sync + guard).
- **Gating.** New collection/environment creation is a workspace-level write →
  `access.require({ type:'workspace', id: activeWorkspaceId, name }, 'write')`.
  Editing/deleting inside a collection → `access.require({ type:'collection',
id }, 'write')`. `move_request` requires write on BOTH source and destination
  collections.
- **Created-id resolution.** `createCollection`/`createFolder` return only a
  snapshot. Snapshot ids before the dispatch, re-list after (`port.listCollections()`),
  and diff to find the new id. Writes are serialized (one in-flight MCP mutation
  at a time) so the diff is unambiguous. `createRequest` id is generated by us
  and returned directly.
- **Error surfacing.** `port.dispatch` returns captured messages; if one is
  `{ type:'toast', level:'error' }` (viewer workspace, missing collection, etc.)
  return it as the tool's error instead of a false success.
- **No secrets, no send.** Environment value writes are out of scope here; no
  tool resolves OAuth tokens or performs HTTP.
  </execution_context>
